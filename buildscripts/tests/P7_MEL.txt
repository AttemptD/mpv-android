P7 MEL -> P8.1 Android native Dolby output

Phone policy: AfuseKt's existing member-only Lua runtime first decodes the
original BL RPU through the GPU path. video-dec-params/dolby-vision-mel allows
promotion only after a canonical zero-residual MEL mapping is seen. The native
converter then validates every access unit independently; a first-frame MEL
classification is not permission to discard a later nonzero FEL residual.

The converter changes the DOVI configuration to P8/CCID1/no EL, removes NLQ,
uses P8.1 matrices, retains BL mapping and supported DM/trim blocks, and removes
EL NALs only after validation. The compressed BL is not re-encoded. Unknown,
corrupt, missing or non-MEL RPUs reject the native path. MediaCodec latches a
conversion failure; it cannot send the unchanged rejected packet on a retry.
mpv reports native runtime failures to the host instead of looping through
software decoders that the native VO cannot present. The host reloads the
original stream with full EL processing, preserving position/pause/playlist.

A device without native Dolby uses the existing GPU HDR path, or GPU SDR
mapping without a PQ-capable screen. FEL always remains in the existing GPU
EL path, subject to the existing P7 performance guard/manual base-layer choice.
The optional TV native-hdr-p7-base flag is not used by the phone Lua policy.
Filters, shaders and explicit software/copy-back selection also retain GPU.
No iOS, EXO or membership entitlement behavior changes.

Conservative boundary: native promotion requires the RPU in the selected
compressed BL stream. Dual-track material whose RPU is carried only in the
separate EL stream remains on GPU; inheriting a decoded EL RPU cannot supply
the missing compressed RPU to a native BL decoder.

Synthetic runtime fixtures
  create-p7-fixture.c links host libavformat.a/libavcodec.a/libavutil.a.
  Arguments: HDR10 MP4, output MP4, one-frame RPU .bin; optionally another RPU
  and switch PTS in seconds. Source MP4 must have 4-byte HEVC NAL lengths.
  Every original BL/AAC packet is retained. EL is a decodable duplicate of BL,
  with matching PTS and HEVC enhancement configuration, for exercising pairing.
  This is not an authored Dolby residual or a visual fidelity reference.
  MEL/FEL use the independent original RPUs above. A deliberately invalid
  MEL->FEL mixed-RPU fixture switches at 5 seconds and removes audio to exercise
  runtime failure at video-only EOF. It must return to the original GPU EL path.
  A full 288-frame MEL clip converted through hevc_mp4toannexb,dovi_mel has
  identical decoded BL frame checksums to the original HDR10 source.
